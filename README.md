## 1. ระบบทำอะไรได้บ้าง

PM Dashboard ช่วยให้ผู้ใช้งาน:

- เปิดแบบฟอร์ม PM ตาม **แผนก → กลุ่มอุปกรณ์ → รหัสอุปกรณ์** ผ่าน Sidebar
- ตรวจรายการ PM โดยเลือก **OK / NO** และใส่ **Result Note** สำหรับบันทึกข้อสังเกต
- บันทึกข้อมูลการตรวจลง **Supabase** โดยไม่ต้องกดปุ่ม Save รวมทั้งฟอร์ม
- ดูความคืบหน้าของการตรวจในหน้า **PM Progress**
- เรียกดูเฉพาะฟอร์มที่มีข้อความ Result Note จริงในหน้า **Result Note**
- ดูภาพรวมข้อมูลย้อนหลังใน **History** และสร้าง *Saved Snapshot* ของรอบ PM
- ดูผู้เปลี่ยนข้อมูลและเวลาที่เปลี่ยนผ่าน **Activity Log**
- จัดการและติดตามกำหนดการตรวจครั้งถัดไปในหน้า **Preventive Maintenance Next Due Date**
- พิมพ์ฟอร์ม PM เป็นกระดาษ A4 หรือเลือก **Save as PDF** จากกล่องพิมพ์ของเบราว์เซอร์
- ให้ Administrator ปรับรายการตรวจเฉพาะอุปกรณ์ เพิ่ม ซ่อน คืนค่า และลบรายการที่สร้างเอง
- ใช้งานได้ทั้งโหมดสว่าง/มืด มีหน้าตาแบบโปร่งแสง และรองรับหน้าจอคอมพิวเตอร์/มือถือ

ข้อมูลฟอร์มในแต่ละอุปกรณ์แยกกัน การแก้รายการของอุปกรณ์หนึ่งจะไม่เปลี่ยนรายการของอุปกรณ์อื่นโดยอัตโนมัติ

## 2. สิทธิ์ผู้ใช้งาน

ระบบอ้างอิงบทบาทจาก `profiles.role` ใน Supabase โดยใช้ค่าตัวพิมพ์เล็กดังนี้:

| การทำงาน | `administrator` | `admin` | `view` |

| เข้าดูฟอร์ม / Progress / Result Note / History | ✅ | ✅ | ✅ |
| บันทึกผลตรวจ OK/NO และ Result Note | ✅ | ✅ | ❌ |
| แก้ไขข้อมูลส่วนหัวฟอร์มและวันที่ PM | ✅ | ✅ | ❌ |
| เพิ่ม / แก้ไข / ซ่อน / คืนค่ารายการตรวจ PM | ✅ | ❌ | ❌ |
| ลบรายการ PM ที่เพิ่มเอง | ✅ | ❌ | ❌ |
| บันทึก Snapshot ประวัติ | ✅ | ✅ | ❌ |
| ล้างผลตรวจ (เมื่อมีฟอร์ม/กลุ่มที่เลือก) | ✅ | ✅ | ❌ |

## 3. เริ่มใช้งานและเข้าสู่ระบบ

### 3.1 เปิดเว็บไซต์

1. เปิดเว็บไซต์ PM Dashboard ของหน่วยงาน (ลิงก์ GitHub Pages ที่ติดตั้งจริง)
2. หน้า **Login** จะมีช่อง **E-Mail** และ **รหัสผ่าน**
3. กรอกอีเมลที่ Administrator สร้างบัญชีให้ แล้วใส่รหัสผ่าน
4. กด **เข้าสู่ระบบ**
5. รอระบบโหลดข้อมูลจาก Supabase จนหน้าแสดงผลพร้อมใช้งาน

**พฤติกรรมของเวอร์ชันปัจจุบัน:** เมื่อ Login ใหม่จะเข้าสู่หน้า **PM Progress Dashboard** เสมอ ไม่กลับไปค้างที่ฟอร์ม PM หรือ Result Note ที่เปิดไว้ก่อนออกจากระบบ

### 3.2 ถ้าลืมรหัสผ่าน

1. ใส่ E-Mail ในหน้า Login
2. กด **ลืมรหัสผ่าน?**
3. เปิดอีเมลที่ได้รับ แล้วทำตามลิงก์สำหรับรีเซ็ตรหัสผ่าน
4. กลับมา Login ด้วยรหัสผ่านใหม่

หากไม่ได้รับอีเมล ให้ตรวจ Spam/Junk และแจ้ง Administrator ตรวจการตั้งค่า Supabase Auth / Redirect URL

### 3.3 ออกจากระบบและปุ่มเปลี่ยนธีม

- กด **ออกจากระบบ** ด้านล่าง Sidebar เมื่อใช้งานเสร็จ
- กด **โหมดมืด / โหมดสว่าง** เพื่อปรับหน้าตา
- ที่ส่วนอีเมลด้านล่าง Sidebar มี **จุดสีเขียวเรืองแสง** แสดงว่าขณะนี้หน้านั้นเข้าสู่ระบบแล้ว **ไม่ใช่** ตัวตรวจสถานะออนไลน์แบบเรียลไทม์ของผู้ใช้ทุกคน
- หากปิดแท็บ/เบราว์เซอร์แล้วเปิดใหม่ ระบบอาจให้ Login ใหม่ตามการจัดการ session ของเวอร์ชันนี้; การกด Refresh ในแท็บเดิมอาจรักษาสถานะ Login ได้

## 4. ทำความรู้จักหน้าจอและ Sidebar

Sidebar รุ่นปัจจุบันแบ่งออกเป็นสองส่วนหลัก:

**กลุ่มฟอร์ม PM ตามแผนก**

- **EM1** — เช่น Flow Meter Unit
- **EM2** — เช่น Letdown Tanks, Delicel Tanks, Additive Tanks, Pigline, Selecta และกลุ่มอื่น ๆ
- **Resin PD1** — เช่น Thinning Tank, Reactor
- **WWT** — เช่น Flow Meter, Conductivity

**เมนูทำงาน / รายงาน**

- **Result Note** — ฟอร์มที่มีข้อความบันทึกในช่อง Result Note
- **PM Progress** — ภาพรวมความคืบหน้า
- **History** — ประวัติและ Snapshot
- **Activity Log** — บันทึกกิจกรรมแก้ไขข้อมูล
- **Preventive Maintenance Next Due Date** — ติดตามกำหนด PM
- **โหมดมืด / สว่าง** — เปลี่ยนธีม
- **ส่งออก PDF / พิมพ์ A4** — พิมพ์ฟอร์มกลุ่มอุปกรณ์ที่เลือก
- **ล้างถังนี้ / ล้างทั้งกรุ๊ป** — ล้างผลตรวจ (โปรดอ่านหัวข้อ 15 ก่อนกด)
- **จัดการผู้ใช้** และ **Login / Export Log** — ปรากฏสำหรับ Administrator

**วิธีใช้เมนูสามชั้น**

1. คลิกชื่อแผนก เช่น **EM2** เพื่อกางรายการ
2. คลิกกลุ่มอุปกรณ์ เช่น **Selecta** เพื่อกางรายชื่อฟอร์ม
3. คลิกรหัสฟอร์ม เช่น **SEL-001** เพื่อเปิดฟอร์มนั้น
4. คลิกชื่อกลุ่มหรือแผนกซ้ำเพื่อยุบเมนู โดยการพับ–กางอย่างเดียวไม่เปลี่ยนผลตรวจ

ใช้ปุ่มลูกศรที่หัว Sidebar เพื่อย่อ/ขยายแถบเมนูบนคอมพิวเตอร์ ส่วนมือถือสามารถเปิด/ปิด Sidebar ผ่านปุ่มเมนูได้

### 4.1 ตัวอย่าง Selecta ใน EM2

ข้อมูลที่เพิ่มจากเอกสาร PM Selecta มี:

| เส้นทางใน Sidebar | Functional Location | จำนวนจุดตรวจที่มีข้อความจริง |
|---|---|---:|
| EM2 → Selecta → **SEL** | `T-M-01-01-SEL` | 8 |
| EM2 → Selecta → **SEL-001** (D01) | `T-M-01-01-SEL-001` | 28 |
| EM2 → Selecta → **SEL-002** (D02) | `T-M-01-01-SEL-002` | 28 |

รวม **64 จุดตรวจ** สำหรับ Selecta ทั้ง 3 ฟอร์ม โดยรายการที่ว่างในต้นฉบับ PDF ไม่ถูกนับเป็นจุดตรวจ

## 5. วิธีตรวจ PM และบันทึกผลทีละขั้นตอน

ตัวอย่าง: **EM2 → Selecta → SEL-001**

### ขั้นตอนที่ 1 — เลือกฟอร์มให้ตรงกับหน้างาน

1. เปิด **EM2** ใน Sidebar
2. เปิดกลุ่ม **Selecta**
3. คลิก **SEL-001** (Selecta D01)
4. ตรวจชื่อแผนก กลุ่ม รหัสอุปกรณ์ และ Functional Location ที่หน้าฟอร์มให้ตรงกับเครื่องที่จะตรวจจริง

### ขั้นตอนที่ 2 — กรอกข้อมูลใบงาน

ในหัวข้อ **Preventive Maintenance Order Info.** สามารถกรอกข้อมูลตามใบงานได้ เช่น:

| ช่อง | ความหมาย / ตัวอย่าง |
|---|---|
| **Order No.** | เลขใบงาน PM ที่ได้รับ |
| **Order Type** | ประเภทใบงาน |
| **Order Activity Type** | ประเภทกิจกรรม |
| **Description** | คำอธิบายงาน |
| **Maintenance Work Center** | ศูนย์งาน / หน่วยงานที่รับผิดชอบ |
| **Supervisor** | ผู้ควบคุมงาน |
| **Order System Status** | สถานะใบงานในระบบ |
| **Order User Status** | สถานะที่ผู้ใช้กำหนด |
| **Order Release Date** | วันที่ปล่อยใบงาน |

กรอกข้อมูลแล้ว **คลิกออกจากช่อง** เพื่อให้คำสั่ง `onchange` บันทึกลง Supabase ไม่ต้องกด Save รวมทั้งหน้า

### ขั้นตอนที่ 3 — ตรวจรายการ PM ทีละบรรทัด

ตารางรายการตรวจแต่ละส่วนมีคอลัมน์หลักดังนี้:

| คอลัมน์ | ความหมาย |
|---|---|
| **Items** | ลำดับรายการตรวจ |
| **Preventive Maintenance Task List** | รายละเอียดสิ่งที่ต้องตรวจ |
| **Standard** | เกณฑ์หรือสภาพที่ยอมรับได้ |
| **Package** | รอบ/แพ็กเกจบำรุงรักษาที่แม่แบบกำหนด เช่น `6M` |
| **OK** | ผลตรวจผ่านตาม Standard |
| **NO** | ผลตรวจไม่ผ่านตาม Standard |
| **Result Note** | คำอธิบายสิ่งที่พบ ข้อบกพร่อง หรือการแก้ไขที่ดำเนินการ |

วิธีทำงาน:

1. อ่าน **Task List** และ **Standard** ก่อน
2. ตรวจอุปกรณ์จริงตามวิธีการของหน่วยงานและกฎความปลอดภัย
3. ถ้าผ่านเกณฑ์ ให้เลือก **OK**; ถ้าไม่ผ่าน ให้เลือก **NO**
4. หากพบสิ่งผิดปกติ ให้พิมพ์รายละเอียดที่ **Result Note** (ควรระบุอาการ/จุด/ค่าที่วัดได้/การดำเนินการ)
5. ทำต่อให้ครบทุกอุปกรณ์ย่อยในฟอร์ม
6. ตรวจความครบถ้วนก่อนเปลี่ยนไปฟอร์มถัดไป

> **วิธียกเลิกผลที่เลือกผิด:** กดตัวเลือก OK หรือ NO ที่กำลังถูกเลือกซ้ำอีกครั้ง เพื่อเปลี่ยนเป็น *ยังไม่เลือก* (ตามพฤติกรรมในโค้ดปัจจุบัน)

**ตัวอย่างการบันทึก:**

- Task: `ตรวจเช็คการทำงานของ Load cell`
- Standard: `อ่านค่าได้ปกติ ค่าไม่สวิง`
- Result: `NO`
- Result Note: `อ่านค่าสวิงขณะไม่มีโหลด ตรวจพบสายสัญญาณหลวม แจ้งซ่อมแล้ว`

### ขั้นตอนที่ 4 — ตรวจว่าบันทึกสำเร็จ

- ระบบจะส่งข้อมูลแต่ละจุดที่เปลี่ยนไปยังตาราง `pm_data` ของ Supabase
- ผล OK/NO ส่งบันทึกเมื่อกด; ช่องข้อความและข้อมูลส่วนหัวส่งเมื่อค่าเปลี่ยนแล้วออกจากช่อง
- ถ้าระบบขึ้นข้อความ **บันทึกไม่สำเร็จ** ให้ตรวจอินเทอร์เน็ตและสิทธิ์ฐานข้อมูล **อย่าสมมติว่าบันทึกสำเร็จ**
- หลังบันทึกสำเร็จ สามารถเปิดฟอร์มเดิมอีกครั้งหรือ Refresh เพื่อตรวจค่าที่บันทึกไว้

> การเลือก `NO` **ไม่ใช่** การปิดงานซ่อมอัตโนมัติ ควรจัดการใบแจ้งซ่อม/การติดตามงานตามกระบวนการจริงของหน่วยงานด้วย

## 6. การกรอกวันที่ PM และ Next Due

หน้า PM มีช่อง:

- **Preventive Maintenance Date** — เดือน/ปีของรอบตรวจ PM
- **Preventive Maintenance Next Due Date** — เดือน/ปีที่ต้องตรวจครั้งต่อไป

การเลือกใช้เดือนและปี (`YYYY-MM` ในฐานข้อมูล) และบนหน้าจออาจแสดง `Nov 2026` เป็นต้น

> [!WARNING]
> **การเปลี่ยนวันที่จากหน้าฟอร์มในเวอร์ชันนี้ใช้ `saveGroupDate()` ซึ่งบันทึกค่าเดียวกันให้ทุกอุปกรณ์ในกลุ่มที่เลือก** (เช่น Selecta ทั้ง 3 ฟอร์ม) ไม่ใช่เฉพาะอุปกรณ์บนหน้าจอ ดังนั้นต้องตรวจให้แน่ใจว่ากลุ่มนั้นใช้รอบ PM เดียวกันก่อนแก้วันที่

หากต้องการเปลี่ยนเดือน Next Due ของแต่ละอุปกรณ์แยกกัน ให้ใช้หน้า **Preventive Maintenance Next Due Date** ที่มีการแก้ค่าจากตารางรายอุปกรณ์ (ตามสิทธิ์ผู้ใช้)

## 7. วิธีใช้ Result Note

หน้า **Result Note** แสดงเฉพาะฟอร์มที่มีข้อความหมายเหตุไม่ว่างและรายการตรวจที่ยังแสดงอยู่ ไม่แสดงแถวที่ถูกซ่อนจากแบบฟอร์ม PM

1. กด **Result Note** ใน Sidebar
2. คลิก **EM1 / EM2 / Resin PD1 / WWT**
3. คลิกกลุ่ม เช่น **Flow Meter Unit / Pigline / Selecta**
4. คลิกชื่อ/รหัสฟอร์มที่ต้องการ เช่น `FMU-004` หรือ `SEL-001`
5. หน้า Result Note จะกรองเฉพาะฟอร์มนั้น
6. คลิก **ดูรายละเอียดหมายเหตุ** เพื่อดูรายการตรวจที่เกี่ยวข้อง สถานะ OK/NO และข้อมูลผู้แก้ไข/เวลาที่มีอยู่
7. คลิก **เปิดฟอร์ม PM** ถ้าต้องการกลับไปดูเช็กลิสต์ต้นฉบับ

เมนูแผนกและกลุ่มสามารถกดซ้ำเพื่อพับ–กางได้ รายชื่อฟอร์มจะแสดงเฉพาะฟอร์มที่มีหมายเหตุจริง ข้อมูล Result Note บนหน้าเว็บเป็นรายงานสำหรับดูข้อมูล ไม่ใช่ช่องแก้ไขหมายเหตุใหม่

การแก้ข้อความหมายเหตุให้กลับไปที่ฟอร์ม PM ต้นฉบับ แล้วแก้ในช่อง Result Note และคลิกออกจากช่องเพื่อบันทึก

## 8. วิธีดู PM Progress

**PM Progress Dashboard** คือหน้าแรกหลังเข้าสู่ระบบ ใช้ดูยอดงาน PM และความคืบหน้าในภาพรวม สามารถใช้ตัวกรองแผนก/กลุ่มและค้นหารหัสอุปกรณ์ได้

ตัวเลขสำคัญในรายงาน:

- **Total / จุดตรวจทั้งหมด** — จำนวนรายการตรวจที่มีจริงและไม่ได้ซ่อน
- **OK** — รายการที่เลือกผ่าน
- **NO** — รายการที่เลือกไม่ผ่าน
- **Pending / ยังไม่ตรวจ** — รายการที่ยังไม่ได้เลือก OK หรือ NO
- **Progress %** — สัดส่วนที่ตรวจแล้ว เทียบกับจำนวนรายการตรวจทั้งหมด

โดยทั่วไปในรายอุปกรณ์:

```text
ตรวจแล้ว (Done) = OK + NO
ยังไม่ตรวจ (Pending) = Total - Done
Progress (%) = Done ÷ Total × 100
```

> **สำคัญ:** ฟอร์มที่มีผล `NO` ก็อาจมี Progress 100% ได้ เพราะ Progress วัดว่า **ตรวจครบหรือไม่** ไม่ใช่แปลว่าทุกจุดผ่าน ควรตรวจยอด NO และ Result Note ประกอบเสมอ

เมื่อผู้ใช้งานเพิ่มรายการตรวจหรือซ่อนรายการผ่านสิทธิ์ Administrator จำนวน Total และเปอร์เซ็นต์จะเปลี่ยนตามรายการที่ใช้งานอยู่

## 9. วิธีใช้ History

**History** มีทั้งภาพรวมรายการอุปกรณ์ที่มีข้อมูล และส่วน **Saved Snapshots** สำหรับเก็บสรุปรอบ PM ณ ขณะนั้น

วิธีดูประวัติ:

1. เปิด **History**
2. เลือกแผนก กลุ่ม สถานะ หรือเดือน PM ที่ต้องการ
3. ใช้ช่องค้นหารหัสอุปกรณ์/Order No. หรือชื่อผู้ควบคุม
4. กด **รีเฟรช** เพื่ออ่านข้อมูลล่าสุด

วิธีบันทึกรอบประวัติ:

1. ตรวจความครบถ้วนของรอบ PM ก่อน
2. กด **บันทึกรอบประวัติปัจจุบัน**
3. ใส่ชื่อ Snapshot เช่น `PM รอบ พ.ย. 2569`
4. ยืนยันให้ระบบบันทึกสรุปของอุปกรณ์ที่เริ่มมีข้อมูลแล้ว
5. ใช้ Saved Snapshots เปรียบเทียบภาพรวมแต่ละรอบ

**ข้อควรรู้:** Snapshot ในโค้ดนี้เป็นการบันทึก **ข้อมูลสรุป** เช่น จำนวน OK/NO, เปอร์เซ็นต์, เดือน PM, ชื่อผู้ตรวจ ไม่ใช่สำเนาฉบับเต็มของทุก Result Note และเก็บ Snapshot ล่าสุดได้สูงสุด **30 รายการ** ในคีย์รวมของ `pm_data`

## 10. วิธีใช้ Activity Log

หน้า **Activity Log** ใช้ตรวจสอบกิจกรรมที่มีข้อมูลบันทึก เช่น การเปลี่ยนผลตรวจ ข้อมูลใบงาน หมายเหตุ หรือวันที่ โดยอาศัยข้อมูล `updated_by` / `updated_at` และการตีความคีย์ในฐานข้อมูล

วิธีใช้:

1. เปิดเมนู **Activity Log**
2. กรองแผนก กลุ่มอุปกรณ์ ประเภทกิจกรรม หรือช่วงเวลา
3. ใช้ช่องค้นหาชื่อผู้ใช้/รหัสอุปกรณ์/ข้อความ
4. กด **รีเฟรช** หรือ **แสดงเพิ่ม** เมื่อต้องการดูข้อมูลเพิ่ม
5. คลิกชื่ออุปกรณ์ที่เป็นลิงก์เพื่อกลับไปดูฟอร์ม PM

> [!NOTE]
> Activity Log ที่ประกอบจากสถานะล่าสุดของ `pm_data` ไม่ได้หมายความว่ามีประวัติทุกเวอร์ชันของการแก้ไขทุกช่องย้อนหลังทั้งหมด หากต้องการระบบ Audit แบบไม่สามารถแก้ไขย้อนหลังได้ ควรใช้ตาราง Audit / Trigger แยกต่างหากฝั่ง Supabase

## 11. วิธีใช้ Preventive Maintenance Next Due Date

หน้านี้ใช้ดูสถานะกำหนด PM ในระดับอุปกรณ์ เช่น:

- **ยังไม่กำหนดวันครบกำหนด** — ยังไม่มีเดือน/ปี Next Due
- **เกินกำหนด** — เดือน Next Due ผ่านมาแล้ว
- **ครบกำหนดเดือนนี้** — Next Due อยู่ในเดือนปัจจุบัน
- **ใกล้ครบกำหนด** — อีก 1–2 เดือน
- **ตามแผน** — มากกว่า 2 เดือนก่อนครบกำหนด

**วิธีดู:** เลือกแผนก กลุ่ม สถานะ เดือนครบกำหนด และค้นหารหัสอุปกรณ์ แล้วกดรีเฟรช

**วิธีแก้เดือน Next Due:** บัญชีที่มีสิทธิ์บันทึกสามารถแก้เดือนรายอุปกรณ์จากตารางในหน้านี้ได้ (ตามตัวควบคุมที่แสดงบนหน้า)

**วิธีตั้งทั้งกลุ่ม:** เลือกกลุ่มอุปกรณ์ในแถบ **ตั้งค่า Next Due Date ทั้งกลุ่มอุปกรณ์** → เลือกเดือน → กด **บันทึกทั้งกรุ๊ป**

> [!WARNING]
> ปุ่ม **บันทึกทั้งกรุ๊ป** เปลี่ยนข้อมูลของสมาชิกในกลุ่มพร้อมกัน ให้ตรวจกลุ่มและเดือนอย่างรอบคอบก่อนบันทึก

## 12. การพิมพ์หรือบันทึกเป็น PDF

หน้าเว็บใช้ระบบพิมพ์ของเบราว์เซอร์ (`window.print()`) โดยปุ่ม **ส่งออก PDF / พิมพ์ A4** ใน Sidebar จะเตรียมฟอร์มของ **ทั้งกลุ่มอุปกรณ์ที่กำลังเลือก** แล้วเปิดกล่องพิมพ์

ขั้นตอน:

1. เปิดฟอร์ม PM ที่อยู่ในกลุ่มที่จะพิมพ์ เช่น **EM2 → Selecta → SEL-001**
2. กด **ส่งออก PDF / พิมพ์ A4**
3. เลือก Printer สำหรับพิมพ์จริง หรือ **Save as PDF** เพื่อบันทึกไฟล์
4. ตั้งค่ากระดาษ **A4 แนวตั้ง**, ขนาด **100%** หรือ Default (ตามตัวอย่างที่พรีวิวแล้วไม่ถูกตัด)
5. ปิด **Headers and footers** ของเบราว์เซอร์ถ้าไม่ต้องการชื่อเว็บไซต์/วันที่บนกระดาษ
6. ตรวจหน้า Preview ก่อนกด Save / Print

**ข้อจำกัดของไฟล์ปัจจุบัน:** ปุ่ม Sidebar `ส่งออก PDF / พิมพ์ A4` พิมพ์ **ทั้งกรุ๊ป** ไม่ใช่เฉพาะฟอร์มที่กำลังเปิด เช่น Selecta จะรวม SEL / SEL-001 / SEL-002 ดังนั้นควรตรวจจำนวนหน้าใน Print Preview ก่อนยืนยัน

**โปรดทราบ:** การ Save as PDF เป็นการสั่งผ่านเบราว์เซอร์ ไม่ได้มีการสร้างไฟล์ PDF ไว้บน Supabase โดยอัตโนมัติ และการเลือกผลตรวจ OK/NO ใน PDF จะปรากฏเฉพาะช่องที่ถูกเลือกไว้

## 13. การแก้ไข เพิ่ม ซ่อน และลบรายการตรวจ PM — Administrator

เฉพาะบัญชี `administrator` เท่านั้นที่ควรเห็นปุ่ม **แก้ไขรายการ PM** เหนือตาราง Checklist หลังเลือกฟอร์มแล้ว

### 13.1 แก้ชื่อรายการตรวจ / Standard / Package

1. เปิดฟอร์ม PM ของอุปกรณ์ที่ต้องการ
2. กด **แก้ไขรายการ PM**
3. เปลี่ยนชื่อรายการ, Standard หรือ Package ในช่องแก้ไข
4. คลิกออกจากช่องเพื่อให้บันทึกอัตโนมัติ
5. กด **เสร็จสิ้นการแก้ไข** เพื่อกลับไปโหมดตรวจ PM

### 13.2 เพิ่มรายการ PM ใหม่

1. เปิดโหมดแก้ไขรายการ
2. ไปที่ส่วนรายการตรวจของอุปกรณ์ย่อยที่ต้องการ
3. ใส่ชื่อรายการ, Standard และ Package ในชุดช่องเพิ่มรายการ
4. กด **เพิ่มรายการ** และตรวจว่ารายการปรากฏ
5. ออกจากโหมดแก้ไขและทดลองเลือก OK/NO ของรายการใหม่

โค้ดรองรับการเพิ่มรายการได้สูงสุด **150 ลำดับต่อส่วนอุปกรณ์ย่อย** (ไม่ใช่ 150 รายการต่อฟอร์มทั้งหมด)

### 13.3 ซ่อน / แสดงรายการ

- **ซ่อนรายการ**: ใช้เมื่อต้องหยุดนับรายการในฟอร์มและ Progress ชั่วคราว
- ข้อมูลผลตรวจเดิมของรายการที่ซ่อน **ยังอยู่** ในฐานข้อมูล
- สามารถแสดงรายการกลับได้ภายหลัง

### 13.4 คืนค่าเดิม

ใช้กับรายการต้นฉบับ เพื่อคืนชื่อรายการ Standard, Package และสถานะซ่อนเป็นค่าแม่แบบเดิม **โดยไม่ลบผล OK/NO และหมายเหตุเดิม**

### 13.5 ลบรายการที่เพิ่มเอง

1. เข้าระบบด้วย `administrator`
2. เปิดฟอร์มและโหมดแก้ไขรายการ
3. กด **ลบรายการ** สีแดงในแถวที่สร้างเพิ่มเอง
4. อ่านข้อความยืนยันก่อนตกลง

> [!CAUTION]
> ปุ่มลบจะลบ **ทั้งข้อมูลรายการที่สร้างเองและผลตรวจ OK/NO / Result Note ของแถวนั้น** ออกจาก Supabase โดยถาวร ในขณะที่รายการต้นฉบับจะใช้วิธี **ซ่อน** แทน ควรสำรองข้อมูลก่อนลบ

การแก้ไขแม่แบบใช้คีย์เฉพาะรหัสอุปกรณ์และส่วนรายการในตาราง `pm_data` โดยไม่แก้ array แม่แบบต้นฉบับใน `js/data/`

## 14. การจัดการผู้ใช้ และ Login / Export Log

### 14.1 จัดการผู้ใช้ (Administrator)

1. เปิด **จัดการผู้ใช้** ใน Sidebar
2. ตรวจรายชื่อบัญชีและสิทธิ์ปัจจุบัน
3. เพิ่มผู้ใช้โดยระบุชื่อ, E-Mail, รหัสผ่าน และ Role ที่ต้องการ
4. หากจำเป็น สามารถเปลี่ยน Role หรือยกเลิกบัญชีตามหน้าจอ
5. ทดสอบ Login ด้วยบัญชีที่สร้างและตรวจว่ามองเห็นเฉพาะปุ่มตามสิทธิ์

**ไม่ควรใช้บัญชี Administrator ร่วมกันหลายคน** เพราะจะตรวจสอบผู้แก้ไขข้อมูลได้ยาก

### 14.2 Login / Export Log (Administrator)

หน้านี้ใช้ตรวจประวัติ Login และคำสั่งส่งออกที่ระบบบันทึก โดยข้อมูลขึ้นกับการติดตั้งตาราง/ฟังก์ชันหลังบ้านที่ใช้งานจริง เช่น `login_logs` และ `export_logs`

หากเปิดหน้าแล้วขึ้น Error เกี่ยวกับตารางหรือ RPC ให้ผู้ดูแลฐานข้อมูลตรวจส่วนติดตั้ง Supabase ก่อน (ไม่ควรแก้ไขจากหน้าเว็บด้วย service role key)

## 15. การล้างผลตรวจ PM และข้อควรระวัง

เมนู **ล้างถังนี้** และ **ล้างทั้งกรุ๊ป** มีผลต่างกัน:

| ปุ่ม | ขอบเขต | สิ่งที่ยังคงอยู่ |
|---|---|---|
| **ล้างถังนี้** | ล้างข้อมูลผลตรวจของอุปกรณ์ที่เลือก | การแก้ไขแม่แบบรายการ PM |
| **ล้างทั้งกรุ๊ป** | ล้างข้อมูลผลตรวจของทุกอุปกรณ์ในกลุ่มปัจจุบัน | การแก้ไขแม่แบบรายการ PM |

**คำเตือน:** แม้แม่แบบยังอยู่ แต่ข้อมูลผลตรวจ/หมายเหตุและข้อมูลส่วนหัวที่เข้าข่ายล้างอาจหายไปจากฐานข้อมูล และข้อมูลรายงานก็เปลี่ยนตาม ควรใช้การเก็บ Snapshot และสำรอง `pm_data` ก่อนล้างทุกครั้ง

ก่อนกดล้าง ให้ตรวจชื่อแผนก กลุ่ม และรหัสอุปกรณ์อีกครั้ง แล้วอ่านข้อความยืนยันให้ครบ

## 16. ข้อมูลและการเชื่อมต่อ Supabase

**สถาปัตยกรรมโดยย่อ**

```text
เว็บเบราว์เซอร์ (GitHub Pages)
        │
        ├── Supabase Auth     → Login / Session
        ├── profiles          → สิทธิ์ administrator, admin, view
        ├── pm_data           → ผลตรวจ, หัวข้อใบงาน, วันที่, หมายเหตุ, การปรับแม่แบบ, Snapshot
        └── ตาราง/ฟังก์ชันเพิ่มเติม (ถ้ามี) → Login / Export Logs, จัดการผู้ใช้
```

`pm_data` ในโค้ดใช้คอลัมน์หลัก ได้แก่ `data_key`, `data_value`, `updated_by`, `updated_at` และมีการ upsert ด้วย `onConflict: "data_key"`

ลักษณะข้อมูลที่บันทึก (เป็นตัวอย่างรูปแบบคีย์):

```text
<equipment>_header_orderNo        → เลขใบงาน
<equipment>_header_pmDate         → เดือน/ปีที่ตรวจ
<equipment>_header_pmNextDate     → เดือน/ปีครบกำหนด
<equipment>_<section>_<row>_radio → OK / NO / ว่าง
<equipment>_<section>_<row>_note  → Result Note
<equipment>_<section>_<row>_taskName / _standard / _package / _hidden → แม่แบบที่แก้เฉพาะอุปกรณ์
```

### ความปลอดภัยที่ต้องตรวจ

1. ใช้ **Supabase Publishable/Anon Key** ที่เหมาะกับการฝังในหน้าเว็บเท่านั้น — **ห้ามใส่ Service Role Key ใน GitHub Pages**
2. ตั้ง **RLS** ให้ `pm_data`, `profiles` และตารางอื่นตามบทบาทที่ต้องการ
3. รันและทดสอบ `sql/pm-template-administrator-only.sql` ตามสภาพฐานข้อมูลจริงก่อนใช้งานการแก้แม่แบบ
4. สำรองข้อมูลก่อนเปลี่ยน SQL/Policy และก่อนล้างผลตรวจจำนวนมาก
5. หากใช้ระบบจัดการบัญชีและบันทึก Login/Export ให้ตรวจว่าฟังก์ชัน/ตารางฝั่ง Supabase ที่ระบบคาดหวังมีอยู่จริง

> [!NOTE]
> การแก้ `README.md`, HTML หรือ JavaScript บน GitHub **ไม่ได้เปลี่ยนข้อมูลใน Supabase** และการอัปโหลดไฟล์ ZIP ก็ **ไม่รัน SQL โดยอัตโนมัติ**

## 19. คำถามที่พบบ่อยและวิธีแก้ปัญหา

<details>
<summary><strong>Q: Login ได้ แต่ไม่เห็นฟอร์ม PM</strong></summary>

- Login ใหม่จะเปิด **PM Progress** ก่อน ให้ขยาย Sidebar เลือก **แผนก → กลุ่ม → ฟอร์ม**
- หาก Sidebar ย่ออยู่ ให้กดปุ่มขยายที่ส่วนหัว
- ถ้าไม่มีข้อมูลในหน้าใด ๆ ให้ตรวจการโหลด Supabase และ Console ของเบราว์เซอร์
</details>

<details>
<summary><strong>Q: Result Note ไม่แสดงฟอร์มที่ต้องการ</strong></summary>

- หน้า Result Note แสดงเฉพาะฟอร์มที่มีข้อความหมายเหตุจริง
- ข้อความว่างหรือหมายเหตุของรายการที่ซ่อนไว้จะไม่ขึ้นในรายงาน
- กลับไปตรวจช่อง Result Note ในฟอร์ม → คลิกออกจากช่อง → กดอัปเดตข้อมูลในหน้า Result Note
</details>

<details>
<summary><strong>Q: ทำไม Progress 100% แต่ยังมี NO</strong></summary>

- Progress นับ **จำนวนจุดที่ตรวจแล้ว** ไม่ใช่จำนวนจุดที่ผ่าน
- ให้ดูยอด NO และ Result Note เพิ่มเติม
</details>

<details>
<summary><strong>Q: กด OK/NO แล้วข้อมูลไม่บันทึก</strong></summary>

- ตรวจอินเทอร์เน็ต สิทธิ์ `admin/administrator`, สถานะ Supabase และข้อความแจ้ง Error
- หากเป็นสิทธิ์ `view` จะดูข้อมูลได้อย่างเดียว
- เปิดฟอร์มใหม่และเช็กค่าอีกครั้งก่อนถือว่าบันทึกสำเร็จ
</details>

<details>
<summary><strong>Q: ไม่เห็นปุ่มแก้ไขรายการ PM</strong></summary>

- ต้อง Login ด้วยบัญชี `administrator` และต้องเลือกฟอร์ม PM ก่อน
- บัญชี `admin` ทั่วไปและ `view` ไม่สามารถแก้แม่แบบได้
</details>

<details>
<summary><strong>Q: กดส่งออก PDF แล้วได้หลายอุปกรณ์</strong></summary>

- ปุ่ม Sidebar ของโค้ดปัจจุบันพิมพ์ **ทั้งกลุ่มอุปกรณ์** ไม่ใช่อุปกรณ์เดียว
- ตรวจ Print Preview และเลือกกลุ่มให้ถูกต้องก่อนพิมพ์
</details>

<details>
<summary><strong>Q: เปลี่ยนวันที่ PM แล้วอุปกรณ์อื่นเปลี่ยนตาม</strong></summary>

- ช่องวันที่บนหน้าเช็กลิสต์บันทึกระดับ **กลุ่ม** ตามการทำงานของ `saveGroupDate()`
- หากต้องการตั้ง Next Due รายอุปกรณ์ ให้ใช้ตารางรายอุปกรณ์ในหน้า Next Due แทน
</details>

<details>
<summary><strong>Q: หน้าเว็บหน่วงเมื่อเปิด Sidebar หรือรายงาน</strong></summary>

- ปิดแท็บที่ไม่จำเป็น ลอง Refresh และอัปเดต Chrome/Edge
- ใช้ Sidebar โดยพับกลุ่มที่ไม่จำเป็น ลดจำนวนรายการที่เบราว์เซอร์แสดงพร้อมกัน

</details>

<details>
<summary><strong>Q: ตัวอักษรไทยหรือขอบ PDF ถูกตัด</strong></summary>

- ตั้ง Scale ตามความเหมาะสม ปิด Headers and footers

</details>

<details>
<summary><strong>Q: ทำไม Logout แล้ว Login ใหม่ไม่กลับไปหน้าที่เคยเปิด</strong></summary>

- เป็นพฤติกรรมที่ตั้งใจของ V19 เป็นต้นมา: เริ่มที่ **PM Progress** ทุกครั้งเพื่อไม่ให้ค้างฟอร์มของผู้ใช้ก่อนหน้า

## 21. การแจ้งเตือน PM ผ่าน LINE ด้วย Google Apps Script

> ส่วนนี้อธิบายไฟล์ `New Text Document.txt` ที่ส่งมาเพิ่มเติม เป็น **สคริปต์แจ้งเตือนภายนอก** ไม่ใช่ฟังก์ชันที่อยู่ในหน้าเว็บ V21 โดยอัตโนมัติ ต้องสร้างโปรเจกต์ Google Apps Script ตั้งค่าสิทธิ์และ Trigger เอง จึงจะทำงานได้  
> **ความปลอดภัย:** ไฟล์ที่ส่งมามี Supabase Secret Key (ขึ้นต้น `sb_secret_`) และ LINE Channel Access Token อยู่จริง ควร **เพิกถอน/หมุนเปลี่ยนทั้งสองคีย์ทันที** ก่อนใช้งานต่อ และห้ามนำค่าเดิม/ค่าใหม่ลง GitHub หรือคู่มือสาธารณะ คู่มือนี้ไม่ทำสำเนาคีย์ทั้งสอง

### 21.1 ภาพรวมการทำงาน

```text
PM Dashboard (ผู้ตรวจ PM)
       │  บันทึกเดือน Next Due
       ▼
Supabase ตาราง pm_data
       │  อ่านเฉพาะคีย์ *_header_pmNextDate
       ▼
Google Apps Script: checkAndNotifyPM()
       │  ตรวจวันที่ 5 และหาเดือน/ปีที่ตรงกับปัจจุบัน
       │  จัดรายชื่ออุปกรณ์ EM1 / EM2 / Resin PD1 / WWT
       ▼
LINE Messaging API: POST /v2/bot/message/broadcast
       │  ส่งข้อความรวม + URL PM Dashboard
       ▼
ผู้ติดตาม LINE Official Account ที่รับ Broadcast ได้
```

ข้อมูลไม่ได้ส่งจากเบราว์เซอร์ไป LINE โดยตรง; Apps Script เป็นตัวกลางที่อ่าน Supabase ผ่าน REST API และส่งข้อความผ่าน LINE Messaging API

### 21.2 อธิบายตัวแปรและฟังก์ชันจากไฟล์

| ส่วนในสคริปต์ | ทำหน้าที่อะไร | สิ่งที่ต้องระวัง |
|---|---|---|
| `SUPABASE_URL` | URL โปรเจกต์ Supabase | URL เป็นค่ากำหนดของโปรเจกต์ |
| `SUPABASE_ANON_KEY` | ชื่อที่ไฟล์ใช้เก็บคีย์สำหรับเรียก REST API | **ชื่อทำให้เข้าใจผิด** เพราะค่าที่ส่งมาเป็น Secret Key ไม่ใช่ Anon/Publishable Key |
| `LINE_CHANNEL_ACCESS_TOKEN` | สิทธิ์ส่งข้อความจาก LINE Official Account | เป็นความลับ ต้องหมุนเปลี่ยนและเก็บใน Script Properties |
| `checkAndNotifyPM()` | ตรวจกำหนดและประกอบข้อความรายเดือน | ต้องมี Time-driven Trigger จึงทำงานอัตโนมัติ |
| `notifyDay = 5` | ให้รันจริงเฉพาะวันที่ 5 ของเดือน | คอมเมนต์ในไฟล์เขียนว่า “วันที่ 1” แต่ค่าที่โค้ดใช้คือ **5** |
| `yyyy_mm` / `format2` | แปลงเดือนเป็น `2026-11` หรือ `11/2026` | ตรวจเพียงเดือน/ปี ไม่ได้ตรวจวันภายในเดือน |
| `data_key=like.*_header_pmNextDate` | อ่านแถวกำหนดตรวจถัดไปจาก `pm_data` | ดึงค่ากำหนดที่บันทึกจริง ไม่ได้คำนวณจาก `Package` |
| `em1List`, `resinList`, `wwtList` | รายการรหัสที่ใช้แยกแผนก | รหัสใหม่หรือที่สะกดไม่ตรงอาจถูกจัดผิด |
| `sendLineBroadcast(message)` | ส่งข้อความหนึ่งชุดผ่าน API Broadcast | ต้องตรวจ HTTP status และโควตา LINE ด้วย |

**สิ่งที่สคริปต์นี้จะทำ**: ถ้าเปิด Trigger ทุกวัน สคริปต์จะหยุดเองในวันที่ไม่ใช่วันที่ 5, หาอุปกรณ์ที่มีเดือน Next Due ตรงกับเดือนปัจจุบัน, จัดกลุ่มตามแผนก, แล้วส่ง LINE เมื่อพบอย่างน้อยหนึ่งรายการ

**สิ่งที่สคริปต์นี้ยังไม่ได้ทำ**: ไม่แจ้งเตือนก่อนถึงกำหนดหลายวัน, ไม่แจ้งรายการค้างเลยเดือนก่อน, ไม่คำนวณรอบ `6M` อัตโนมัติ, ไม่รู้ว่า OK/NO ครบแล้วหรือยัง, และยังไม่มีระบบกันแจ้งเตือนซ้ำเมื่อเรียกฟังก์ชันหลายครั้งภายในวันที่ 5

### 21.3 ตัวอย่างการอ่านข้อมูล Supabase

เมื่อกรอก **Preventive Maintenance Next Due Date** ของรหัส `FMU-001` และ `T5120` เป็นเดือน `2026-11` โค้ดคาดว่ามีข้อมูลรูปแบบใกล้เคียงต่อไปนี้ใน `pm_data`:

```text
data_key                     data_value
------------------------------------------------
FMU-001_header_pmNextDate    2026-11
T5120_header_pmNextDate      2026-11
```

สคริปต์ตัดข้อความท้าย `_header_pmNextDate` เพื่อให้เหลือรหัสอุปกรณ์ เช่น `FMU-001` และ `T5120` จึงรองรับรหัสที่มีเครื่องหมายขีดกลางได้ โดยไม่ใช้ `split('_')`

**ตรวจสอบก่อนเริ่มใช้งาน:**

1. เปิดฟอร์ม PM หรือหน้า Next Due แล้วตรวจว่าได้บันทึกเดือนถัดไปจริง
2. ยืนยันว่าคอลัมน์ข้อมูลใน `pm_data` ชื่อ `data_key` และ `data_value` ตามที่สคริปต์ใช้
3. ตรวจว่าค่าเป็น `YYYY-MM` หรือ `MM/YYYY` ตามที่โค้ดเทียบ ไม่ใช่วันที่เต็มแบบ `YYYY-MM-DD`
4. หากข้อมูลจำนวนมาก ต้องพิจารณาการแบ่งหน้า REST API (pagination) แทนการสมมติว่าคำตอบครั้งเดียวมีทุกแถว
5. ถ้าต้องการแจ้งรายการค้างกำหนด (เดือนที่ผ่านมา) ต้องเพิ่มเงื่อนไขใหม่ ไม่ใช่แค่เทียบเท่ากับเดือนนี้

### 21.5 ตั้งค่า Google Apps Script ให้ปลอดภัย

1. **หมุนเปลี่ยนคีย์ที่อยู่ในไฟล์เดิมก่อน**: ที่ Supabase ให้สร้างคีย์ใหม่/เพิกถอนคีย์ที่รั่ว และที่ LINE Developers ให้ออก Channel Access Token ใหม่/ยกเลิก Token เดิมตามชนิด Token ที่ใช้อยู่
2. เปิด [Google Apps Script](https://script.google.com/) และสร้างโปรเจกต์สำหรับแจ้งเตือน PM แยกจากเว็บ GitHub Pages
3. ไปที่ **Project Settings → Script properties** แล้วเพิ่มคีย์ชื่อ `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `LINE_CHANNEL_ACCESS_TOKEN` โดยใส่ **ค่าใหม่** ในช่อง Value (อย่าแชร์ภาพหน้าจอที่แสดงค่า)
4. ใน `Code.gs` เปลี่ยนตัวแปรคงที่ที่ฝังคีย์ในซอร์สโค้ดเป็นการอ่านจาก Script Properties แทน:

```javascript
const props = PropertiesService.getScriptProperties();
const SUPABASE_URL = props.getProperty('SUPABASE_URL');
const SUPABASE_SECRET_KEY = props.getProperty('SUPABASE_SECRET_KEY');
const LINE_CHANNEL_ACCESS_TOKEN = props.getProperty('LINE_CHANNEL_ACCESS_TOKEN');

if (!SUPABASE_URL || !SUPABASE_SECRET_KEY || !LINE_CHANNEL_ACCESS_TOKEN) {
  throw new Error('Missing Script Properties');
}
```

5. ปรับส่วนดึงข้อมูล Supabase ให้ส่ง `sb_secret_...` ผ่าน **`apikey` เท่านั้น** อย่าส่งคีย์ชนิดนี้ใน `Authorization: Bearer ...` เพราะ Supabase อาจตีความเป็น JWT และตอบ `Invalid JWT` ตัวอย่างส่วนหัวที่ถูกต้องสำหรับ **คีย์ Secret รุ่นใหม่**:

```javascript
const options = {
  method: 'get',
  headers: { apikey: SUPABASE_SECRET_KEY },
  muteHttpExceptions: true
};
```

> ไม่ควรคัดลอกคีย์ Secret ไปไว้ใน `config.js`, `index.html`, README หรือไฟล์บน GitHub Pages เพราะคีย์ชนิดนี้สามารถข้าม Row Level Security (RLS) ได้ แม้จะถูกนำไปใช้เฉพาะเพื่ออ่านข้อมูลก็ตาม Script Properties ช่วยแยกคีย์จากซอร์สโค้ด แต่ยังต้องจำกัดสิทธิ์ผู้ที่แก้ไขโปรเจกต์ Apps Script ด้วย

### 21.6 ตั้งเวลาให้ตรวจสอบทุกวัน

1. เปิด Apps Script และเลือกฟังก์ชัน `checkAndNotifyPM`
2. ตั้งค่า Time zone ของโปรเจกต์เป็น **Asia/Bangkok**
3. เปิดเมนู **Triggers** (ไอคอนรูปนาฬิกา) → **Add Trigger**
4. เลือกฟังก์ชัน `checkAndNotifyPM`, Event source เป็น **Time-driven**, ประเภทเป็น **Day timer** แล้วเลือกช่วงเวลาเช้า เช่น 08:00–09:00
5. อนุญาตสิทธิ์ที่ Apps Script ขอสำหรับการเรียก URL ภายนอก (`UrlFetchApp`)
6. สคริปต์จะถูกเรียกทุกวัน แต่ส่งเฉพาะวันที่ `notifyDay` ตรงกับวันที่ในโปรเจกต์

> ควรใช้เขตเวลาเดียวกันทั้ง Script Project, การตรวจวันที่ และการแสดงเดือน (Asia/Bangkok) โค้ดเดิมใช้ `Utilities.formatDate(..., "Asia/Bangkok", ...)` เฉพาะบางส่วน แต่ `today.getDate()` / `today.getMonth()` อาจอิงเขตเวลาของ Script Project ซึ่งทำให้การคำนวณใกล้เที่ยงคืนไม่ตรงกันได้

**การทดลองแบบปลอดภัย:** ก่อนรันจริงให้ลองตรวจเพียงผลการอ่านข้อมูลจาก Supabase และแสดงรายชื่อใน Execution log โดย **ไม่เรียก `sendLineBroadcast`** จนกว่าจะตรวจรายชื่อและจำนวนผู้รับถูกต้อง การกด Run ในวันอื่นจะออกจากฟังก์ชันตั้งแต่เงื่อนไข `notifyDay` และไม่ทดสอบการเชื่อมต่อที่เหลือ

### 21.7 ส่งข้อความไปที่ไหน: Broadcast หรือกลุ่ม LINE?

โค้ดในไฟล์ใช้ endpoint `POST https://api.line.me/v2/bot/message/broadcast` เพื่อส่งข้อความ **ถึงผู้ใช้ที่เป็นเพื่อนกับ LINE Official Account** ตามหลักของ Broadcast ไม่ใช่การเลือกส่งเข้า Group chat แบบเจาะจง

ถ้าต้องการส่งเข้า **กลุ่ม LINE ของแผนก** โดยตรง ต้องใช้การส่งประเภท **Push message** และกำหนด `groupId`/ปลายทางที่ถูกต้อง รวมถึงตั้งค่าอนุญาตให้บอทเข้ากลุ่ม (ต้องดำเนินการเพิ่มเติม) ไม่ควรคาดหวังว่า Broadcast เดิมจะส่งเข้ากลุ่มได้

ข้อมูลเพิ่มเติม:
- [LINE Messaging API — Sending messages](https://developers.line.biz/en/docs/messaging-api/sending-messages/)
- [LINE Messaging API — Group chats](https://developers.line.biz/en/docs/messaging-api/group-chats/)

### 21.8 ตรวจผลลัพธ์และแก้ปัญหา

| อาการ | ตรวจสอบอะไร | แนวทางแก้ |
|---|---|---|
| ไม่ส่ง LINE เลย | วันที่ปัจจุบันตรง `notifyDay` หรือไม่, มี Trigger หรือไม่ | ตรวจ Execution log; ใช้โหมดทดสอบอ่านข้อมูลโดยไม่ส่งก่อน |
| Supabase ตอบ `401` / `Invalid JWT` | ส่ง `sb_secret_...` ผ่าน `Authorization: Bearer` หรือไม่ | ใช้ `apikey` สำหรับ Secret Key ชนิดใหม่ และตรวจว่าคีย์ยังใช้งานได้ |
| ไม่เห็นอุปกรณ์บางตัว | `pmNextDate` ว่าง/รูปแบบต่างกัน/มีผลลัพธ์เกินขีดจำกัดรายการ REST | ตรวจข้อมูลจริงและเพิ่ม pagination เมื่อจำเป็น |
| อุปกรณ์อยู่ผิดแผนก | ตารางรหัสอุปกรณ์เขียนคงที่ | ใช้แมปแผนกจาก PM Dashboard และปรับเมื่อเพิ่มฟอร์มใหม่ |
| ส่งข้อความซ้ำในวันที่ 5 | ไม่มีตัวบันทึกว่าเดือนนี้ส่งแล้ว | ใช้ Script Properties เก็บเดือนที่ส่งสำเร็จ; บันทึกหลังเช็กว่า LINE ตอบสำเร็จเท่านั้น |
| LINE ไม่มีผู้รับหรือส่งไม่ผ่าน | บัญชีปลายทางเป็นเพื่อน OA หรือยัง, โควตา/Token ถูกต้องหรือไม่ | ตรวจ HTTP status และรายละเอียดตอบกลับจาก LINE; อย่า log Token |
| LINE ไม่เข้ากลุ่ม | ใช้ Broadcast ไม่ใช่ Push to group | เปลี่ยนวิธีส่งและตั้งค่ากลุ่มให้รองรับบอท |

**ตรวจ HTTP status ของ LINE**: ฟังก์ชัน `sendLineBroadcast()` ในไฟล์เดิมเรียก `UrlFetchApp.fetch()` แต่ไม่ตรวจ `getResponseCode()` จึงอาจไม่พบข้อผิดพลาดชัดเจนเมื่อ LINE ตอบ 400/401/429 ควรแยกการส่งสำเร็จ/ล้มเหลว และเก็บเฉพาะข้อความตอบกลับที่ไม่ใช่ความลับใน Log

**ป้องกันส่งซ้ำ**: ใช้คีย์ เช่น `PM_LINE_LAST_SENT_MONTH` ใน Script Properties เก็บค่า `2026-11` **หลังจากส่งสำเร็จเท่านั้น** และเช็กค่าดังกล่าวก่อนส่ง (การทำงานพร้อมกันหลายครั้งควรพิจารณา `LockService` เพิ่มเติม)

### 21.9 ข้อจำกัดและข้อเสนอแนะก่อนใช้งานจริง

- ใช้โปรเจกต์ทดสอบ หรือโหมดแสดงรายชื่อก่อนยิง LINE ถึงทุกคน เพราะ Broadcast อาจถูกคิดตามจำนวนผู้รับและโควตาบัญชี
- ทดสอบการแจ้งเตือนรายเดือนกับข้อมูลจำลองของ EM1 / EM2 / Resin PD1 / WWT ก่อนนำไปใช้จริง
- เก็บเฉพาะคีย์ที่จำเป็นใน Script Properties; จำกัดสิทธิ์ผู้แก้ไขโปรเจกต์ และหมุนเปลี่ยนคีย์ตามนโยบายองค์กร
- หากต้องการดูว่างานใด **ยังไม่ตรวจ / ตรวจแล้ว / พบ NO / เลยกำหนด** ต้องเพิ่มการอ่านข้อมูลสถานะจากตาราง `pm_data` และนิยามเงื่อนไขอย่างชัดเจน โค้ดปัจจุบันตรวจเฉพาะเดือน `pmNextDate` เท่านั้น
- Google Apps Script แจ้งเตือน LINE เป็นระบบเสริมแยกต่างหาก; การอัปเดต README หรือเว็บ GitHub Pages **ไม่ใช่** การตั้ง Trigger, สร้าง LINE OA หรือเพิ่มสิทธิ์ Supabase ให้โดยอัตโนมัติ
