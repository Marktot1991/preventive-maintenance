# Preventive Maintenance Form

โครงสร้างหลังแยกไฟล์ (โหลดตามลำดับใน index.html — ห้ามสลับลำดับ)

- index.html — โครงหน้าเว็บ (HTML)
- config.js — ไฟล์ตั้งค่า Supabase (ต้องเพิ่มเอง ไม่ได้อยู่ในไฟล์ต้นฉบับ)
- css/ — สไตล์แยกตามหัวข้อ
- js/ — โค้ดแยกตามหน้าที่ (state, auth, data, form-render, progress, export-pdf ฯลฯ)
  - js/data/ — รายชื่อถัง/อุปกรณ์/แม่แบบ checklist


## การปรับปรุงประสิทธิภาพ (Performance)

- แคชข้อมูลรายงาน History / Next Due และ Activity Log ระหว่างเปลี่ยนตัวกรอง เพื่อลดการวนสร้างข้อมูลซ้ำ
- ล้างแคชอัตโนมัติเมื่อโหลดข้อมูลใหม่หรือบันทึกข้อมูล เพื่อให้รายงานไม่แสดงข้อมูลเก่า
- โหลดรายชื่อโปรไฟล์เพียงครั้งเดียวต่อ session และบังคับโหลดใหม่หลังเพิ่มผู้ใช้
- หน่วงการค้นหา (Debounce) ในหน้า Progress, History, Activity และ Admin Logs ให้รอพิมพ์เสร็จก่อนวาดหน้าจอ
- หน้า Admin Logs สร้างตารางเฉพาะแท็บที่กำลังเปิด ลดจำนวนแถว DOM ที่ต้องวาดพร้อมกัน
- ย้าย `css/performance.css` ไว้ท้ายสุด เพื่อให้กฎลดเอฟเฟกต์มีผลจริงหลัง CSS อื่น

หมายเหตุ: การปรับปรุงนี้ลดงานซ้ำฝั่งเบราว์เซอร์ แต่ความเร็วการโหลดข้อมูลครั้งแรกยังขึ้นกับจำนวนแถวใน Supabase, อินเทอร์เน็ต และ Index / RLS Policy ของตารางด้วย


## ปรับปรุง Sidebar

- Desktop ใช้ CSS class สำหรับพับ/ขยาย แทนการเขียน inline style และวนแก้เมนูทีละรายการ
- ไม่ animate `width`, `margin-left` และ `left` บน Desktop เพื่อลดการคำนวณ layout ซ้ำระหว่างการกดพับ/ขยาย
- Mobile ยังคงใช้การเลื่อน Sidebar ด้วย `transform` ซึ่งไม่เปลี่ยน layout ของเนื้อหาหลัก


## แก้ไขรายการ PM เฉพาะอุปกรณ์ (เพิ่มในเวอร์ชันนี้)

1. เข้าระบบด้วยผู้ใช้สิทธิ์ `administrator` เท่านั้น แล้วเลือกกลุ่มและรหัสถัง/อุปกรณ์ในหน้า PM Form
2. กด **แก้ไขรายการ PM** เหนือ Checklist (ปุ่มจะไม่แสดงสำหรับสิทธิ์ `admin` และ `view`)
3. แก้ชื่อรายการ, Standard หรือ Package ได้ทันที เมื่อออกจากช่อง ระบบจะบันทึก Supabase `pm_data` ผ่าน `saveDataToServer()`
4. ใต้ตารางของแต่ละอุปกรณ์สามารถ **เพิ่มรายการ**, **ซ่อน/แสดงรายการ** และ **คืนค่าเดิม** (สำหรับรายการต้นฉบับ)
5. กด **เสร็จสิ้นการแก้ไข** เพื่อกลับไปบันทึกผล OK/NO และหมายเหตุแบบปกติ

รายการแก้ไขเก็บเป็น key รูปแบบ `<tank>_<section>_<row>_taskName`, `_standard`, `_package`, `_hidden` และ `<tank>_<section>_customMax` ใน Supabase `pm_data` ไม่แก้แม่แบบใน `js/data/` และไม่ต้องสร้างตารางใหม่ แต่**ต้องรัน `sql/pm-template-administrator-only.sql` ใน Supabase SQL Editor** เพื่อบังคับสิทธิ์ฝั่งฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่ม

**สำคัญ:** ปุ่ม **ล้างถังนี้** และ **ล้างทั้งกรุ๊ป** ปรับให้ล้างเฉพาะผลตรวจโดยเก็บรายการแม่แบบ PM ที่แก้ไขไว้แล้ว กรุณาสำรองข้อมูลก่อนใช้ และตรวจสิทธิ์/RLS บน Supabase ก่อนนำขึ้นระบบจริง


## การจำกัดสิทธิ์แก้ไขรายการ PM เฉพาะ Administrator

| สิทธิ์ | กรอกผลตรวจ OK/NO / หมายเหตุ | แก้ไข เพิ่ม ซ่อน คืนค่าแม่แบบ PM |
|---|---|---|
| `administrator` | ได้ | ได้ |
| `admin` | ได้ | ไม่ได้ |
| `view` | ดูอย่างเดียว | ไม่ได้ |

โค้ดหน้าเว็บซ่อนปุ่มและตรวจสิทธิ์ก่อนบันทึก แต่การป้องกันไม่ให้เรียก Supabase API โดยตรงต้องใช้การตรวจบนเซิร์ฟเวอร์ด้วย:

1. สำรองฐานข้อมูล Supabase
2. เปิด Supabase Dashboard > SQL Editor แล้ววาง/รัน `sql/pm-template-administrator-only.sql`
3. ตรวจว่าบัญชี Administrator มี `profiles.role = 'administrator'` ตรงตัว
4. ลองล็อกอินด้วย `admin` และ `administrator` เพื่อตรวจปุ่มและการบันทึก

SQL จะติดตั้ง trigger ให้ `pm_data` ตรวจ `profiles.role` จาก `auth.uid()` ทุกครั้งที่มีการ INSERT / UPDATE / DELETE ของคีย์แม่แบบ PM (suffix `_taskName`, `_standard`, `_package`, `_hidden`, `_customMax`) โดยบัญชี `admin` และ `view` จะถูกปฏิเสธจากฐานข้อมูลด้วย นอกจากนี้ SQL ยังป้องกันผู้ใช้ทั่วไปเปลี่ยน `profiles.role` ของตนเองเป็น `administrator` (ยังคงรองรับคำสั่งจัดการสิทธิ์จาก Administrator และ service role) ไม่เปลี่ยนสิทธิ์บันทึกผลตรวจปกติ และไม่ใช้ service role key บนหน้าเว็บ

หมายเหตุ: การติดตั้ง SQL ต้องทำเองใน Supabase โปรเจกต์ที่ใช้จริง เนื่องจาก ZIP เป็นโค้ดหน้าเว็บที่ไม่มีสิทธิ์แก้ไขฐานข้อมูลของคุณอัตโนมัติ


### ลบรายการตรวจ PM ที่เพิ่มเอง (Administrator เท่านั้น)
เข้าสู่ระบบด้วย `administrator` > เลือกถัง/อุปกรณ์ > **แก้ไขรายการ PM** > ที่แถวรายการที่เพิ่มใหม่ กดปุ่มสีแดง **ลบรายการ** และยืนยัน
ระบบจะลบข้อมูลรายการและผลตรวจเฉพาะแถวนั้นใน Supabase; ไม่มีผลต่ออุปกรณ์อื่น
รายการตรวจต้นฉบับจะไม่ปรากฏปุ่มลบ ให้ใช้ **ซ่อนรายการ** แทนเพื่อป้องกันการลบผิดพลาด
กรุณาสำรองข้อมูลและติดตั้ง SQL ใน `sql/pm-template-administrator-only.sql` เพื่อป้องกันการแก้ไข/ลบแม่แบบโดยบัญชีอื่นในระดับฐานข้อมูล
