# Preventive Maintenance Form

โครงสร้างหลังแยกไฟล์ (โหลดตามลำดับใน index.html — ห้ามสลับลำดับ)

- index.html — โครงหน้าเว็บ (HTML)
- config.js — ไฟล์ตั้งค่า Supabase (ต้องเพิ่มเอง ไม่ได้อยู่ในไฟล์ต้นฉบับ)
- css/ — สไตล์แยกตามหัวข้อ
- js/ — โค้ดแยกตามหน้าที่ (state, auth, data, form-render, progress, export-pdf ฯลฯ)
  - js/data/ — รายชื่อถัง/อุปกรณ์/แม่แบบ checklist


## การปรับปรุงประสิทธิภาพ (Performance)

- แคชข้อมูลรายงาน History / Next Due และ Activity Log ระหว่างเปลี่ยนตัวกรอง เพื่อลดการวนสร้างข้อมูลซ้ำ
- ล้างแคชอัตโนมัติเมื่อโหลดข้อมูลใหม่หรือบันทึกข้อมูล เพื่อให้รายงานไม่แสดงข้อมูลเก่า
- โหลดรายชื่อโปรไฟล์เพียงครั้งเดียวต่อ session และบังคับโหลดใหม่หลังเพิ่มผู้ใช้
- หน่วงการค้นหา (Debounce) ในหน้า Progress, History, Activity และ Admin Logs ให้รอพิมพ์เสร็จก่อนวาดหน้าจอ
- หน้า Admin Logs สร้างตารางเฉพาะแท็บที่กำลังเปิด ลดจำนวนแถว DOM ที่ต้องวาดพร้อมกัน
- ย้าย `css/performance.css` ไว้ท้ายสุด เพื่อให้กฎลดเอฟเฟกต์มีผลจริงหลัง CSS อื่น

หมายเหตุ: การปรับปรุงนี้ลดงานซ้ำฝั่งเบราว์เซอร์ แต่ความเร็วการโหลดข้อมูลครั้งแรกยังขึ้นกับจำนวนแถวใน Supabase, อินเทอร์เน็ต และ Index / RLS Policy ของตารางด้วย


## ปรับปรุง Sidebar

- Desktop ใช้ CSS class สำหรับพับ/ขยาย แทนการเขียน inline style และวนแก้เมนูทีละรายการ
- ไม่ animate `width`, `margin-left` และ `left` บน Desktop เพื่อลดการคำนวณ layout ซ้ำระหว่างการกดพับ/ขยาย
- Mobile ยังคงใช้การเลื่อน Sidebar ด้วย `transform` ซึ่งไม่เปลี่ยน layout ของเนื้อหาหลัก
